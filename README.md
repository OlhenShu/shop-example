# shop-example

Навчальний магазин на Vite і React. На сторінці є картки товарів, кошик і журнал подій. Журнал показує, яка подія сталася і на якому елементі.

## Запуск

```powershell
npm install
npm run dev
```

Відкрий адресу, яку надрукує Vite, зазвичай http://localhost:5173.

Інші команди:

- `npm run build` збирає проєкт у папку `dist`
- `npm run preview` показує вже зібрану версію
- `npm run lint` перевіряє код ESLint

## Що на екрані

Ліворуч сітка товарів. На картці є назва, ціна, поле кількості і кнопка **Додати**. Клік по самій картці підсвічує її.

Праворуч кошик: список доданих позицій, кнопки **+1** і **Прибрати**, сума. Під кошиком журнал останніх семи подій.

## Файли

`index.html` — порожня сторінка з `<div id="root">`. Увесь інтерфейс React малює в цей елемент.

`vite.config.js` — підключає плагін React, щоб Vite розумів JSX.

`src/main.jsx` — точка входу. Знаходить `root` і малює `App` у `StrictMode`.

`src/index.css` — загальний шрифт, фон і відступи сторінки.

`src/App.jsx` — шапка з назвою і підказкою. Сам магазин не збирає, лише вставляє `Catalog`.

`src/App.css` — вигляд карток, сітки, кошика і журналу.

`src/Catalog.jsx` — дані товарів і вся логіка. Тут живуть стан, обробники і форма додавання.

`src/ProductCard.jsx` — оболонка однієї картки. Отримує назву, ціну і колір пропсами, а форму приймає як `children`.

`src/Cart.jsx` — лише показує кошик. Список і сума рахуються з пропа `items`. Кнопки викликають функції, які передав батько.

## Хто батько, а хто нащадок

`Catalog` — батько. Він вирішує, що робити після кліку, і передає це вниз.

`ProductCard` і `Cart` — нащадки. Вони малюють розмітку і викликають отримані функції.

Форма `ProductCartButton` вкладена між тегами `ProductCard`, тому вона є `children` картки і з’являється під ціною.

```jsx
<ProductCard title={product.title} price={product.price}>
  <ProductCartButton onAdd={(event) => handleAdd(event, product)} />
</ProductCard>
```

## Події

Обробник отримує об’єкт події першим аргументом.

- `event.type` — назва події: `change`, `click` або `submit`.
- `event.target` — елемент, де подія почалася.
- `event.target.value` — поточний текст поля кількості.
- `event.currentTarget` — елемент, на якому висить обробник, що зараз виконується.

Клік по **Додати** дає два рядки в журналі. Спочатку `currentTarget` це `BUTTON`. Потім подія спливає до `<article>`, і `currentTarget` стає `ARTICLE`. `target` в обох рядках лишається `BUTTON`, бо клік почався на кнопці.

Клік по заголовку картки кнопки не чіпає. У журналі один рядок: `target H2`, `currentTarget ARTICLE`.

Відправлення форми обробляє `handleAdd` у `Catalog`. `event.preventDefault()` скасовує перезавантаження сторінки. Кількість читається з форми через `event.target.elements.qty`.

## Стан

У `Catalog` три виклики `useState`:

- `cart` — масив позицій кошика. Початкове значення `[]`.
- `selectedId` — id підсвіченої картки.
- `trace` — останні рядки журналу.

Новий масив у стан кладе функція-оновлювач. React передає їй попереднє значення як `prev`.

- Додати: `setCart((prev) => [...prev, нова позиція])`.
- Збільшити кількість: `map` повертає новий масив, у потрібного рядка новий об’єкт з `qty + 1`.
- Прибрати: `filter` повертає новий масив без цього рядка.
- Журнал: новий рядок ставиться на початок, лишаються лише 7 останніх.

`pushTrace` викликається вручну з кожного обробника. Сама зміна `cart` журнал не заповнює. Тому запис про **Прибрати** і **+1** стоїть поруч із `setCart` у `handleRemove` і `handleIncrease`.

`traceId` — це `useRef`. Лічильник дає кожному рядку журналу стабільний `id` для ключа і не скидається під час перемальовування.

## Списки і ключі

Товари малюються через `products.map`. Ключ картки — `product.id`, він не змінюється.

Рядки кошика теж малюються через `map`. Ключ — `lineId`, новий для кожного додавання. Той самий товар можна покласти в кошик кілька разів, і React не плутає ці рядки.

Журнал малюється окремим `map`, ключ рядка — `entry.id`.
